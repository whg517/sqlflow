## 结论等级

- **通过**：关键用户旅程、服务端门禁和运行保障均有可重复证据。
- **有条件通过**：不存在阻断发布的问题，剩余问题有明确责任人和关闭期限。
- **有条件不通过**：设计方向可行，但存在阻断日常工作或生产发布的问题。
- **不通过**：核心方案无法满足目标，需要调整产品边界或架构决策。

## 问题关闭规则

1. 问题关闭必须同时更新实现、自动化测试和对应需求状态。
2. 安全问题不得仅通过隐藏菜单、补充说明或依赖人工约定关闭。
3. P0 必须有跨层回归测试；P1 至少有服务层或 API 层自动化测试。
4. 改变授权模型、部署拓扑、元数据存储或任务可靠性语义时，先新增 ADR。
