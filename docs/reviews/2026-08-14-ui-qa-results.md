## 新缺陷

### UI-FINDING-1 [Medium·已修复] Web Vitals 上报在生产模式 100% 失效

- **现象**：浏览器控制台持续出现 `POST /api/metrics/web-vitals 400`，随后 429（限流）。
- **根因**：`web/src/shared/lib/web-vitals.ts` 用 `navigator.sendBeacon(url, jsonString)` 发送纯字符串。浏览器对字符串 beacon 固定使用 `Content-Type: text/plain`，而 Echo 的 `c.Bind` 仅按 `application/json` 解析，导致载荷绑定失败 → `请求格式错误` 400。指标多次上报又触发每 IP 10 次/分钟限流 → 429。**该功能自上线起从未成功上报过。**
- **验证**：`curl` 对照实验确认 `text/plain` → 400、`application/json` → 200。
- **修复**：beacon 载荷包成 `new Blob([body], {type: "application/json"})`，使 sendBeacon 携带正确 Content-Type。
- **测试**：更新 `web-vitals.test.ts` 断言（Blob 类型 + 内容）；前端全量 610/610 通过。
- **端到端验证**：重建 dist → 清浏览器缓存硬刷新 → 真实交互触发上报 → 服务端日志 200。
- **顺带解释**：2026-08-13 QA 报告里查询工作台的"神秘一次性 400"即同源。
