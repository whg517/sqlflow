## 1. 执行摘要

模块化单体、SQLite 平台元数据、Driver 能力模型和“查询—工单—审计”闭环适合当前单实例、小团队定位，项目具备继续演进的基础。但当前实现不能被视为生产级数据库治理系统：

- Developer/DBA 的默认权限链路已修复；数据源发现仍待隔离 E2E 完成关闭。
- 结果分享、资源所有权、多语句分析与执行之间存在安全缺陷。
- 定时工单、临时权限、API Token Scope 等关键能力虽有代码入口，但不形成有效的端到端行为。
- 备份、恢复、关闭、监控和发布门禁不足以支撑可证明的生产恢复能力。

因此，当前更接近**受控内部验证版本**。在 [阶段 0](../ROADMAP.md#阶段-0安全止血与主流程恢复p0) 完成前，不应连接高价值生产数据源，也不应对外开放结果分享。

## 3. P0：发布阻断问题

### REV-P0-001 密码保护的结果分享可被直接读取（已修复）

- **证据**：`internal/service/share.go` 在密码校验前组装并返回结果行；公开 GET Handler 直接返回该对象。验证接口成功后也没有产生可供后续读取验证的会话或凭证。
- **影响**：持有链接 Token 的访问者可绕过分享密码读取数据。
- **关闭标准**：
  - 密码保护的分享在未验证时绝不返回列、行或敏感元数据。
  - 验证后使用短期、绑定分享记录的不可伪造授权证明。
  - 增加“直接 GET、错误密码、正确密码、过期、撤销”的 API 回归测试。
- **关闭证据（2026-07-26）**：
  - 未验证读取只返回 `has_password`、`access_granted=false` 和时间信息，列、行、SQL 摘要、数据源名称及真实记录 ID 不返回。
  - 验证成功后签发最长 15 分钟、绑定分享 ID/Token 的 HMAC 证明，通过 `HttpOnly`、`SameSite=Strict` Cookie 传递；过期、篡改、跨分享、链接过期或撤销时均不能使用。
  - GET 和验证响应使用 `Cache-Control: no-store`；分享 Service 与 Handler 定向回归、前端生产构建通过。

### REV-P0-002 普通用户无法发现可用数据源（实现完成，待隔离 E2E 关闭）

- **证据**：`GET /api/datasources` 注册在 Admin 路由组；查询页和新建工单页以普通认证用户身份调用该接口，并吞掉失败。
- **影响**：Developer/DBA 无法完成查询、提单和权限申请等核心日常工作。
- **关闭标准**：
  - 提供认证用户可用的“可访问数据源摘要”接口，不泄露凭据和管理字段。
  - 前端显式呈现 401/403/空授权状态。
  - Developer 与 DBA 的 Playwright 主流程可以选择数据源并继续操作。
- **关闭证据（2026-07-26）**：
  - 新增认证路由 `GET /api/datasources/available`，仅查询活动数据源并返回 `id/name/type/status`；管理接口仍保持 Admin-only。
  - 查询、工单创建/筛选、权限申请和审计筛选改用安全摘要接口；空列表和加载错误不再被静默吞掉。
  - Handler 回归验证禁用数据源不会出现，且响应不含主机、端口、用户名、数据库、连接池或 ES 配置；前端 TicketNew 29 个用例和生产构建通过。
  - 已新增 Developer、DBA、匿名用户的 Playwright 场景；本机首次拉取 MySQL E2E 镜像耗时过长而中止，测试栈已清理，故本问题暂不计为关闭。
  - 该接口只负责发现，不授予查询权限；实际访问仍由服务端授权门禁决定，相关默认策略问题由 REV-P0-003 跟踪。

### REV-P0-003 默认 Casbin 策略不产生预期权限（已修复）

- **证据**：matcher 使用严格相等，种子策略却使用字面量 `*`；查询鉴权使用 `role + ds_<id> + table` 元组。空库种子策略测试被跳过。
- **影响**：默认 Developer/DBA 查询可能全部被拒绝；若后续局部修补，亦可能造成语义不一致的越权。
- **关闭标准**：
  - 用 ADR 固化 subject、domain、object、action 的唯一格式与通配语义。
  - 种子策略、管理 API、临时权限和所有消费端共享同一构造函数。
  - 从空数据库启动，验证三种内置角色的允许/拒绝矩阵。
- **关闭证据（2026-07-29）**：
  - [ADR-0006](../adr/0006-canonical-casbin-tuples.md) 固化 `role/user:<id> + ds_<id> + object + action` 格式与策略侧通配语义。
  - 新增 `internal/authz` 统一构造和规范化；查询、导出、脱敏、工单、权限 Middleware、管理 API 与临时权限已切换。
  - Casbin matcher 支持策略侧 Domain/Object/Action 通配；管理 API 拒绝非规范域和未知动作。
  - 取消空库种子测试跳过，验证 9 条种子策略及 Admin/DBA/Developer 真实 `ds_17/orders` 允许—拒绝矩阵；临时权限批准与撤销使用规范元组回归通过。

### REV-P0-004 多语句分析与实际执行对象不一致

- **证据**：MySQL/PostgreSQL 解析器只分析首条语句，查询执行路径可把原始完整 SQL 交给驱动。
- **影响**：`SELECT; UPDATE` 一类输入可能绕过只读门禁；实际可利用性仍需目标数据库集成测试确认，但设计不变量已被破坏。
- **关闭标准**：
  - 查询入口默认拒绝多语句，或逐条完整解析并仅执行已验证语句。
  - 解析、权限、审计和执行使用同一规范化语句集合。
  - 为 MySQL 和 PostgreSQL 增加真实驱动的负向集成测试。

### REV-P0-005 生产示例暴露固定 MySQL root 凭据

- **证据**：`.env.example` 提供固定示例 root 密码；`docker-compose.yml` 使用 root、暴露 `3306`，并把示例目标库作为 SQLFlow 启动依赖。
- **影响**：照抄部署可能向宿主网络暴露已知高权限凭据，并把非核心示例组件变为平台可用性依赖。
- **关闭标准**：
  - 生产 Compose 不启动或不对外暴露示例目标库。
  - 示例库使用随机/显式必填的最小权限账号。
  - 开发示例与生产模板分离，启动前校验危险默认值。

### REV-P0-006 备份不能证明一致、可恢复和异地可用

- **证据**：WAL checkpoint 失败被视为非致命后继续直接复制数据库文件；备份与主库默认位于同一 Volume；没有恢复命令、完整性校验、加密、异地复制或恢复演练。
- **影响**：故障时可能只有“备份文件存在”，但无法满足恢复点和恢复时间目标。
- **关闭标准**：
  - 使用 SQLite 官方一致性备份方式，并在产物上执行完整性校验。
  - 提供受控恢复命令和恢复前备份；记录操作审计。
  - 定义 RPO/RTO、异地副本、加密和季度恢复演练。

## 4. P1：核心能力与安全完整性

| ID | 问题 | 影响/证据摘要 | 关闭方向 |
|---|---|---|---|
| REV-P1-001 | 临时权限不参与实际查询 | 批准时写入 `user:<id>` 和裸数据源 ID，查询/导出使用 role 与 `ds_<id>`；过期清理无周期调度 | 统一授权元组并增加到期/撤销集成测试 |
| REV-P1-002 | API Token Scope 未执行 | `RequireScope` 未挂路由；Token 被固定映射为 `api_token` 角色且无对应策略 | Scope 作为服务端门禁，限制可申请 Scope，并定义与 RBAC 的组合规则 |

| REV-P1-004 | 工单及执行结果缺少资源隔离 | 详情、列表、结果/导出依赖认证或客户端可选 scope，没有稳定所有者/审批者过滤 | 服务端统一资源授权策略 |
| REV-P1-005 | 私有 SQL 模板可被他人读取/渲染 | 按 ID 获取和渲染时未校验当前用户 | 所有者或公开可见性检查及负向测试 |
| REV-P1-006 | 风险等级可受客户端影响 | Handler 接受 `risk_level`/AI 结果，Service 仅在字段为空时计算，可能改变审批策略 | 服务端重新计算并把客户端结果仅作非权威输入 |
| REV-P1-007 | 审批与重提缺少原子性 | 多阶段更新缺少事务/CAS；重提不重新分析、评估风险和匹配策略 | 事务化状态迁移，重提走完整创建评估链 |
| REV-P1-008 | 异步导出目录错误 | Container 把 SQLite 文件路径当数据目录，再追加 `/exports` | 使用独立 DataDir 配置并做启动期可写检查 |
| REV-P1-009 | 多数据源工单前端路径不完整 | 非 MongoDB 被统一映射为 MySQL；MongoDB/ES 提交流程可能传空 SQL | 以 Driver Capability 驱动 UI，覆盖 PostgreSQL/MongoDB/ES E2E |
| REV-P1-010 | 权限拒绝被返回为 500 | Service 返回普通格式化错误，Handler 缺少稳定领域错误映射 | 统一 401/403/404/409 领域错误 |
| REV-P1-011 | 非 TLS 启动缺少优雅关闭 | signal 和 `Shutdown` 只在 TLS 分支执行 | 统一 Server 生命周期并配置读写/空闲超时 |
| REV-P1-012 | 菜单与 API 角色边界不一致 | 审计、报表、设置、覆盖度等导航对普通用户可见，后端多为 Admin-only 或禁用 | 共享能力矩阵；UI 只改善体验，服务端仍独立授权 |

## 5. 运维主管意见

以下问题不一定单独阻断本地开发，但在生产发布前必须进入运行基线：

- 示例 YAML 含已知 JWT、管理员密码和固定 AES 密钥；当前启动校验只覆盖部分危险默认值。
- 访问日志包含完整 URI，可能记录分享 Token、OIDC code/state；`/metrics` 公开且标签可能含数据源名称。
- 发布流水线先推送镜像后扫描，扫描 Action 使用可变的 `master` 引用，漏洞检查不能作为发布门禁。
- 指标存在“已声明但未更新”，没有告警、Dashboard、SLO、容量或磁盘阈值配置。
- 新旧连接池对 readiness 的定义不同；健康版本硬编码；指标端口配置与实际路由不一致。
- 日志格式混合且缺少 request ID；备份文件权限和 API 返回的服务器文件路径违反最小暴露原则。
- CORS 默认过宽；Docker 与 CI 的 Node 版本及依赖安装方式不一致。

## 6. 架构师意见

架构方向可以继续使用，无需因本次评审立即拆分微服务。优先修复以下跨模块不变量：

1. **唯一授权上下文**：主体、业务角色、Token Scope、资源所有权、数据源域和动作必须形成一致的服务端决策输入。
2. **分析即执行对象**：被解析、评估、批准、审计的语句必须与最终交给 Driver 的语句完全一致。
3. **状态机单写入口**：审批、调度、执行、取消和重提只能通过带 CAS/事务的领域操作迁移。
4. **能力驱动界面**：前后端依据 Driver Capability 决定支持路径，不能用“非 MongoDB 即 MySQL”一类推断。
5. **可恢复才算备份**：产物、校验、恢复工具、异地保存和演练共同构成恢复能力。

授权模型修正和调度可靠性语义需要新增 ADR；其余问题可在现有架构内迭代。

## 7. 开发者意见

代码已具备较多 Service、测试和驱动抽象，可采用纵向切片修复，而不是大规模重写。建议每个切片包含：

- 一条可运行的角色旅程；
- Handler 与 Service 的服务端授权；
- 数据迁移或兼容处理；
- 明确领域错误；
- Go/API 测试与关键 Playwright 场景；
- 对应需求状态更新。

优先切片为“Developer 发现数据源并只读查询”，随后是“分享安全”“工单所有权与风险”“定时执行”“临时权限/API Token”。
