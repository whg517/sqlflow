# ADR-0005：在服务端集中执行权限、状态机与脱敏门禁

- 状态：accepted
- 日期：2026-07-14（补录）
- 决策者：SQLFlow Team
- 关联需求：FR-SEC-001 至 FR-SEC-005、NFR-SEC-001
- 取代：无
- 被取代：无

## 背景

SQLFlow 的前端会根据用户角色隐藏或禁用部分操作，但浏览器和 API Client 可被操控。如果授权仅存在于 UI 或路由层，用户可能直接调用端点、访问他人资源、重复执行工单或导出未脱敏数据。

## 决策

服务端按纵深防御执行安全规则：Middleware 完成身份和粗粒度管理边界；Service 校验资源所有权、角色、Casbin 策略、临时权限、工单状态和并发前置条件；结果返回前统一执行字段脱敏。前端权限控制只用于改善体验。

## 备选方案

- 只使用前端路由和菜单控制：实现简单，但不构成安全边界。
- 只使用路由 RBAC：适合粗粒度角色，无法覆盖数据源、表、动作和资源所有权。
- 依赖目标数据库账号授权：能提供底层保护，但难以表达平台工单状态、临时权限、脱敏和统一审计。

## 后果

- 优点：API 直接调用与 UI 操作具有相同安全结果；策略可集中测试和审计。
- 代价：Handler/Middleware、Service 和 Casbin 之间需要清晰分工，避免重复或不一致校验。
- 约束：新增查询、导出、分享或执行入口必须复用相同权限与脱敏规则，并测试越权失败路径。

## 验证

- 路由区分 public、authenticated 和 admin groups。
- Service 测试覆盖角色、资源所有权、临时权限和非法状态迁移。
- 查询导出与结果返回共用权限、敏感表和脱敏规则。
