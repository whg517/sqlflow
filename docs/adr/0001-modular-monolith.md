# ADR-0001：采用模块化单体和单一部署单元

- 状态：accepted
- 日期：2026-07-14（补录）
- 决策者：SQLFlow Team
- 关联需求：NFR-MNT-001、NFR-DEP-001
- 取代：无
- 被取代：无

## 背景

SQLFlow 同时包含认证、查询、工单、审批、审计、通知和运维能力。这些能力共享用户、数据源、权限和工单状态，要求强一致的本地事务与简单部署。当前产品面向小团队自托管场景，独立拆分服务会增加网络故障、分布式事务和运维成本。

## 决策

采用 Go 模块化单体：Echo Handler 负责协议适配，Service 负责用例和业务规则，DB/Driver/外部 Adapter 负责基础设施。React SPA 与 Go API 构建进同一镜像并由同一进程提供服务；调度器和后台服务也在进程内运行。

## 备选方案

- 微服务：边界可独立扩展，但当前规模下会引入不必要的部署、观测和一致性复杂度。
- 前后端独立部署：可独立发布，但会增加 CORS、版本兼容和静态托管配置。
- Serverless 函数：不适合当前长连接驱动池、进程内调度和 SQLite 文件存储。

## 后果

- 优点：部署简单；本地调用和事务边界清晰；开发、测试与故障排查成本低。
- 代价：所有模块共同发布；单进程资源相互影响；进程内任务阻碍无协调的多副本部署。
- 约束：模块必须通过清晰依赖方向维持边界，不能把“单体”演变成跨层任意调用。

## 验证

- `internal/app.Container` 统一装配和管理生命周期。
- `internal/api`、`internal/service`、`internal/driver` 和 `internal/db` 保持职责分离。
- Dockerfile 产出包含 Go 服务和 `web/dist` 的单一运行镜像。
