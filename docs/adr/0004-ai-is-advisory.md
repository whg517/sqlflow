# ADR-0004：AI 评审只作辅助并提供确定性规则降级

- 状态：accepted
- 日期：2026-07-14（补录）
- 决策者：SQLFlow Team
- 关联需求：FR-QRY-004、FR-TKT-002
- 取代：无
- 被取代：无

## 背景

大模型可以为 SQL 风险、索引和优化提供有价值的解释，但外部服务存在未配置、超时、限流、输出不稳定和数据边界风险。数据库授权和执行不能依赖概率性输出，也不能因 AI 不可用而完全中断治理流程。

## 决策

AI 评审作为建议能力，通过流式接口向用户返回风险与优化信息。SQL parser、风险规则、Casbin 权限、敏感表规则和工单状态机仍是确定性门禁；AI 未配置或调用失败时回退到规则结果，不赋予额外权限，也不直接触发执行。

## 备选方案

- AI 是强制审批器：解释能力强，但不可用性和非确定性不可接受。
- 完全不使用 AI：最稳定，但丢失对复杂 SQL 的辅助解释和优化建议。
- 在客户端直接调用 AI：会暴露密钥、绕过审计并使提示词和数据边界不可控。

## 后果

- 优点：外围服务失败不阻断核心流程；安全决策可测试、可复现。
- 代价：规则引擎需要持续维护；AI 建议可能与最终门禁结论不同。
- 约束：任何 AI 新能力都必须明确其输入数据、超时、降级和审计策略。

## 验证

- `AIReviewService` 支持多个 Provider 和超时配置。
- 查询和工单流程在没有 AI Key 时仍可执行确定性分析。
- 执行授权最终由 Service 权限和状态校验决定。
