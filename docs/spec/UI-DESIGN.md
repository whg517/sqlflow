Source of truth: yes

## 1. 设计目标

SQLFlow 是面向开发者、DBA 和管理员的工作台型产品。界面应优先服务高频操作、风险判断和可追溯治理，而不是营销展示。

设计目标：

- 信息密度适中，便于扫描、筛选和比较。
- 风险、权限、状态和结果反馈清晰。
- 查询、审批、配置等高频流程路径短。
- 不同角色看到的能力边界明确。
- 深色和浅色主题都保持可读、稳定和专业。

## 2. 信息架构

主导航按工作任务组织：

| 区域 | 页面 | 主要用户 |
|------|------|----------|
| 总览 | Dashboard | admin、dba |
| 查询 | Query | developer、dba、admin |
| 工单 | Ticket、TicketNew | developer、dba、admin |
| 权限 | Permissions、Permission Requests | developer、dba、admin |
| 治理 | Audit、Reports、Performance、Coverage | dba、admin |
| 管理 | Users、Settings、Token、SQL Templates | admin 或登录用户 |
| 公开访问 | Login、Shared Result | 访客 |

导航可根据角色隐藏不可用入口，但不能替代后端权限。

## 3. 页面布局

- 桌面端使用侧边栏 + 顶栏 + 内容区。
- 内容区以工作台布局为主，避免营销式大 hero。
- 查询、工单、审计、报表等页面优先提供筛选区、主表格、详情抽屉或弹窗。
- 设置页使用 tabs 分组，避免把所有配置放进单个长页面。
- 移动端应保证关键操作可访问，但后台治理场景以桌面优先。

## 4. 视觉规范

### 色彩

- 主色用于主要操作、当前导航和焦点态。
- 风险色必须稳定：低风险绿色，中风险黄色/橙色，高风险红色。
- 禁止仅靠颜色表达状态，必须配合文本、图标或 badge。
- 深浅主题的色彩 token 由 CSS 变量控制。

### 字体与密度

- 工作台页面使用紧凑但可读的字号和行高。
- 表格、筛选、弹窗中的标题不使用 hero 级字号。
- 长 SQL、错误信息、审计详情使用等宽字体。

### 间距

- 页面级、区块级、组件级、元素级间距应有明显层级。
- 表格和表单控件高度保持稳定，加载和错误状态不得造成明显布局跳动。

## 5. 组件规范

| 组件 | 用法 |
|------|------|
| Button | 明确动作；危险动作使用 destructive 样式并要求确认 |
| Badge | 表达状态、风险、角色、数据源类型 |
| Table | 用于查询结果、工单、审计、用户、策略等可比较数据 |
| Dialog | 用于短流程创建、确认和测试连接 |
| Sheet | 用于工单详情、审计详情、复杂对象详情 |
| Tabs | 用于设置和治理页面的同级分组 |
| Select | 用于枚举选择，不用于自由输入 |
| Tooltip | 解释图标按钮和截断文本 |
| Toast | 用于操作结果反馈，不承载复杂错误排查 |

## 6. 核心交互

### 查询页

- 数据源选择、编辑器、AI 评审、执行结果应保持在同一工作流中。
- AI 评审需要展示风险等级、决策、建议和降级状态。
- 查询结果表支持分页、列筛选、导出和脱敏提示。
- 多数据源差异必须在操作前提示，不在失败后才暴露。

### 工单页

- 工单列表突出状态、风险、提交人、数据源、更新时间和 SLA。
- 工单详情展示 SQL、评审结果、审批链、评论、执行结果和审计线索。
- 审批、驳回、取消、执行和定时执行必须有二次确认。
- 被驳回工单的重提路径应保留上下文。

### 设置页

- 系统设置按 AI、通知、飞书、Webhook、SLA、审批策略、脱敏规则等分组。
- 测试类动作必须给出明确成功/失败原因。
- 密钥、Token、Webhook secret 等敏感值默认隐藏。

### 审计与报表

- 审计检索强调时间、用户、动作、数据源和关键字。
- 审计详情应展示请求对象、结果、错误和关联实体。
- 报表用于趋势和定位，不替代审计明细。

## 7. 状态设计

每个页面至少覆盖：

- 初始加载。
- 空数据。
- 筛选无结果。
- 网络错误。
- 403 无权限。
- 表单校验失败。
- 后台任务运行中。
- 操作成功和失败。

高风险操作必须具备可恢复或可解释的失败反馈。

## 8. 无障碍与可用性

- 所有交互控件必须支持键盘焦点。
- 图标按钮必须有可访问名称。
- 表单错误必须靠近字段展示。
- Dialog 和 Sheet 需要正确管理焦点。
- 文本对比度必须满足常规工作环境可读性。

## 9. 前端治理规则

- 新页面必须复用 `components/ui` 基础组件。
- 新 API 调用必须放在 `web/src/api`。
- 新复杂状态优先抽到 hook 或 store。
- 新表格必须定义空态、加载态和错误态。
- 涉及权限的 UI 必须以后端 403 为兜底。
- 涉及视觉 token 的变更必须同时验证深色和浅色主题。
